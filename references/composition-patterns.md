# Composition Patterns

Choose exactly one pattern per image. Treat these as starting structures, not templates to copy. Do not combine pattern names in the prompt or shot list; if a path contains several moments, it is still the `Path` pattern, not a path plus comic or workflow.

## Workflow

Use for input → processing → output, content production, AI workflows, or automation. Put the input and output at opposite sides; let the cat perform the transformation in the middle. Use blue for the main structure and pink for the key result or signal.

## System slice

Use for sources, filters, model context, agents, or a small system. Show only 3–5 modules or objects. The cat must operate one important part of the system.

## Before and after

Use for manual versus automated, scattered versus organized, confused versus stable, or noisy versus clear. Keep the comparison simple and let the cat physically move, compress, sort, or repair the transition.

## Character state

Use for creator pain, tool overload, blocked work, or a change in confidence. Show 2–4 states at most. Each state needs one action, not a paragraph of labels.

## Conceptual metaphor

Use for an abstract claim. Convert the idea into one physical action and one low-tech object: a drawer, tube, box, door, scale, net, workbench, or strange machine. Use the cat as the operator, not as decoration.

## Layering

Use for method stacks, capability layers, or content systems. Use a few rounded layers or objects rather than a formal pyramid. Let the cat carry, place, or connect one layer.

## Path or mini-comic

Use for a journey, process, failure-to-success sequence, or short story. Use one curved path or 2–4 small scenes. Do not expand a single-image request into a storyboard unless the user asks for it.

## Originality rule

Start from the current idea and invent a fresh physical metaphor. Do not copy the reference image's object arrangement, workflow cards, or character pose. Preserve only the brand language, character invariants, line density, and restraint.
